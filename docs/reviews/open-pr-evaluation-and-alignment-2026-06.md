## 1. TL;DR

The backlog is **one release PR to resolve and four stale feature PRs to retire**. Release PR **#199 (2.3.1)** is mechanically clean and up-to-date but **must not be merged as-is**: it is blocked by a real, non-flaky consumer-compat failure (`ottochain-services` imports `normalizeMessage`, which #197 removed) and is mis-labeled — #197 dropped a public export and #206 renamed oracle→script, both consumer-breaking, yet conventional-commits cut it as a **patch**. The other four PRs (**#41**, **#95**, **#80**, **#83**) are all **close/supersede**: the delegation pair (#41 SDK module + #95 proto) has **no on-chain counterpart** (chain PR #90 closed; chain defers delegation to issue #29) and references JLVM context vars the chain never injects; #80's 4-bit TDEG token model was **superseded by the chain's 5-bit TSCEG RFC v2** (every test integer is now wrong); #83 is **already-merged subscription/CI work + a docs-only spec for an unbuilt, unblockable feature**. **Conflicts / dependencies.** Depends on **#41** (`delegation.isAuthorized` surface) and **#95** (proto half). ## 5. SDK ↔ OttoChain Alignment Gaps (by area, prioritized by severity)

### 5a. Signing & canonical compatibility

> **Core crypto is aligned.** `src/ottochain/drop-nulls.ts` byte-matches metakit `JsonBinaryCodec.dropNulls` (drop null object fields recursively, preserve array nulls) and is applied internally + unconditionally in dataUpdate mode on every signer + verify — exactly metakit's post-2026-06-10 mandate; content-hash.md even names the SDK's `dropNulls` as a conformance target. The new **Σ-protocol opcodes do NOT touch signing** — they're JLVM guard/effect opcodes (`prove_dlog_verify`, `prove_dhtuple_verify`, `sigma_verify`) and no proof-carrying fields were added to any DataUpdate schema. The real divergences are in the **registry signed-message schema**.

| Sev | Topic | Gap | Fix |
|-----|-------|-----|-----|
| **HIGH** | `PublishVersion` split | Chain split into `PublishMachineVersion{...machineShape}` + `PublishScriptVersion{...scriptShape, scriptProgram}` and replaced `SchemaShape` with the `MachineShape`/`ScriptShape`/`RegistryShape` ADT; SDK still ships one `PublishVersion{schemaShape, definition}` (`types.ts:501`) + tag `'PublishVersion'`. Field set, message-type tag, and shape ADT all differ → chain can't decode, tag no longer routes → hard reject. | Replace the single `PublishVersion` type + tag with `PublishMachineVersion` + `PublishScriptVersion` mirroring `Updates.scala`; introduce `MachineShape`/`ScriptShape`(MethodDispatch)/`RegistryShape` to replace `SchemaShape`; update `OttochainMessage` union, `OTTOCHAIN_MESSAGE_TYPES`, builders/exports; add a round-trip case mirroring `PublishVersionSigningCanonicalSuite`. |
| **HIGH** | `strict` required-non-defaulted | Chain `PublishMachineVersion.strict`/`PublishScriptVersion.strict`/`RegisteredVersion.strict` are plain `Boolean` with **no default**; `useDefaults=true` only refills fields that *have* a default, so omitting `strict` **fails the Circe decode outright** (harder than `InvalidSignature`). SDK types `strict?: boolean` "defaults to false; omittable" (`types.ts:204`, `:512`). | Make `strict: boolean` **required** on the new publish types + `RegisteredVersion`; correct the doc comments — client MUST send it. Matches `docs/signing-and-publishing.md` rule 2 + chain signing-canonical invariant #1. |
| **HIGH** | `FieldShape.repeated`/`optional` required | Chain `FieldShape.repeated`/`optional: Boolean` have **no defaults** (required), nested inside the signed `MachineShape`/`ScriptShape` payload. SDK types `repeated?`/`optional?` "omittable" (`types.ts:140-146`). Omitting → undecodable canonical → reject. | Make `repeated: boolean; optional: boolean` **required** on `FieldShape` + fix the wire comment. (`genesis-manifest.ts` already types `repeated` as required — align the public type with it.) |

### 5c. Fiber-app definitions vs chain

> The chain is **entirely app-agnostic** — on-chain it only knows `StateMachineDefinition{states, initialState, transitions, metadata}`, `State{id, isFinal, metadata}`, `Transition{from, to, eventName, guard, effect, dependencies: Set[UUID]}`. It has **no** identity/governance/markets apps, no `createSchema`/`eventSchemas`, no `emits` on transitions, and no `$timestamp` key. The SDK layers a richer schema on top; the `toProtoDefinition()` bridge is meant to strip down but is **opt-in and buggy**.

| Sev | Topic | Gap | Fix |
|-----|-------|-----|-----|
| **CRITICAL** | `dependencies`: object `DependencySpec` vs `Set[UUID]` | SDK `Transition.dependencies` allows `DependencySpec{machine, instanceRef, requiredState}`; corporate machines (`corp-entity.ts` L476-480/L646-655, corp-board/securities/shareholders) emit object-form deps, and `toProtoDefinition()` passes them through (L322). | **HIGH** | `$timestamp` used pervasively but absent on-chain | 20 state machines (~150+ occurrences) use `{var:"$timestamp"}` in effects (`activatedAt`/`suspendedAt`/`createdAt`, e.g. `identity-agent.ts:206`). `ContextProvider.buildContextData` injects only state/event/.../`$ordinal`/`$epochProgress`/`$lastSnapshotHash`/proofs/machines/parent/children/scripts/heldAssets — **no `$timestamp`**.
